# G27.02.a — Add the manual theme preference when dark mode is approved

## Epic

Epic: #346

## Goal

Give Settings one persistent system/light/dark control if 436 (архіўны рэпе) approves a dark theme; keep the released screen honest if the dark-theme verdict chooses light only.

## Acceptance criteria

1. [ ] Read the dark-theme owner verdict (картка 436 архіўнага рэпе; рашэнне DT-1 у `docs/design/brand/decisions.md`). If dark mode is approved, add one Settings control with system, light and dark choices; if the verdict is light only, record that the control is omitted and close this task without a dead row.
2. [ ] For an approved dark theme, persist the manual choice locally; system follows live OS changes, and the selected theme applies to app chrome without changing active Run state, audio or content artwork.
3. [ ] Test restart, offline use, live OS theme changes, status bar and large text in both themes; ensure the control and its labels remain accessible. A revert of persistence or theme application fails a test.

## Out of scope

Designing dark tokens in place of the dark-theme task (436, архіўны рэпе), inverting illustrations, guide filtering or collection mechanics.

## Dependencies

Blocked-by: #782, 436 (архіўны рэпе — цёмная тэма прынята, DT-1).

## Proof

Theme preference, system-following and Run-continuity tests; device screenshots of both themes when dark mode is approved. For light-only, cite the dark-theme verdict's recorded decision (436, архіўны рэпе) and the absence of the control.
