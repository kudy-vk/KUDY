## Што зроблена

- `tools/ci/ci-local.mjs` — `significantCommands`: зачыненыя дзве слепыя
  зоны з issue:
  - **складаная каманда** (`cd web && npm test`) — npm/npx/node супадзенне
    шукаецца па ўсім радку, не толькі ў пачатку; уся радок становіцца
    істотнай камандай і мусіць быць пакрытай ci:local-запісам цалкам;
  - **env-прэфіксавая** (`ENV=val npm ci`) — гэтак сама.
- `sudo ` пераведзены з plumbing-спісу ў prefix-strip побач з `exec `:
  sudo запускае тую каманду, што ідзе пасля яго (`sudo npm ci` — гэта
  `npm ci`), а `sudo apt-get install …` так і застаецца plumbing-адмовай
  (без npm/npx/node супадзення). Раней `sudo npm ci` маўкліва выпадаў
  двойчы: як plumbing і па simple-prefix правіле.
- Plumbing (set/export/test/echo/printf/mkdir/grep/read і чыстыя
  прысвойванні) не змяніўся: `export KUDY_CHROMIUM="$(node -e …)"` як і
  раней не істотная каманда — пазіцыя запінена тэстам і коментарам.
- `tools/ci/ci-local.test.mjs`: +2 тэсты — helper-пін кампанундаў
  (compound, env-прэфікс, `sudo npm ci` → `npm ci`, `sudo apt-get …` → не
  істотная, export → не істотная) і production-path revert-тэст:
  `parseWorkflowJobs` → `coverageFailures` валіць гвардыю з імем кроку на
  нескрытай `cd web && npm test`.
