## Epic

`Epic: #95`

## Goal

Білды sandbox-APK — **па запыце**, не пасля кожнага пуша (рашэнне ўладальніка
2026-11-17, каментар у гэтай задачы). Два шляхі запуску: кнопка на працоўным
стале ўласніка (eas build з сесіі хоста — не патрабуе CI і сакрэтаў, можа
працаваць ужо да гэтай задачы) і кнопка «Run workflow» у GitHub
(workflow_dispatch — даступна адкуль заўгодна; патрабуе EXPO_TOKEN secret).
Падзенне зборкі — чырвоны статус і каментар пра падзенне; паўторныя зборкі
сама ствараюць гісторыю версій (#95 AC4); runbook фіксуе працэдуру выбару
старой версіі і адкату.

Спека: `docs/superpowers/specs/2026-11-17-phone-builds-eas/spec.md` (рашэнне 3 —
білд па запыце).

## Acceptance criteria

1. [ ] Кнопка на працоўным стале: запуск `tools/phone-build/build-on-demand.sh`
   дае хмарную зборку `sandbox`, паведамленне на стале пра запуск і пра
   гатоўнасць з спасылкай на старонку зборкі (QR); ахоўны тэст ланцера пады
   пры вяртанні профілю, палера або пры ўвядзенні токенаў у скрып.
2. [ ] `workflow_dispatch` («Run workflow» у GitHub UI альбо `gh workflow run`)
   → хмарная зборка sandbox-APK; спасылка на старонку зборкі (APK + QR) у job
   summary і каментар у гэтай задачы.
3. [ ] Падзенне хмарнай зборкі → чырвоны статус workflow і каментар пра падзенне
   са спасылкай на лаг (#95 AC5: не лічыць PASS пры няўдачы build/check/upload).
4. [ ] Сакрэт-гігіена (#95 AC5): EXPO_TOKEN толькі ў GitHub secret, не ў
   гіце/лагах/каментарах; падзенне пры адсутным сакрэце дае чырвоны статус з
   агульным тлумачэннем без значэння сакрэту.
5. [ ] Трыгер не прымае код/сакрэты з недаверанага PR і не абыходзіць required
   checks (workflow_dispatch толькі на main; улік guard-required-checks).
6. [ ] Зборка ідзе ў хмары: CI-ранер толькі адпраўляе зборку ў EAS і чакае
   спасылку — native-зборкі на ранеры няма.
7. [ ] Гісторыя версій (#95 AC4): пасля ≥ 3 зборак каталог білдаў паказвае
   versionName, versionCode, commit SHA, дату і статус; працэдура выбару старой
   версіі і вяртання да яе запісана ў runbook (з улікам Android downgrade і
   магчымай страты лакальных тэставых даных — не абяцаць захавання, калі
   Android патрабуе выдалення апкі).
8. [ ] Негатыўны ахоўны тэст (#95 AC7): праверка падае, калі release пазначаны
   апублікаваным без APK, правільнага package ID, подпісу, SHA або працоўнай
   спасылкі.
9. [ ] Runbook дапоўнены (#95 AC7): шляхі запуску (стал/GitHub), што рабіць пры
   падзенні, гісторыя і адкат; па-беларуску.

runbook. Кнопка стала не патрабуе ні CI, ні сакрэтаў — яна працуе ўжо ў
PHONE-01.
