## Epic

`Epic: #95`

## Goal

Пасля мержа змястоўных змен у main CI сам запускае хмарную зборку
sandbox-APK і пакідае каментар у змержаным PR: спасылка на старонку зборкі з
QR і кароткі «як усталяваць». Упадзе зборка — чырвоны чэк на main і каментар
пра падзенне. Docs-only змены зборку не тратяць; ручны запуск па кнопке
заўсёды даступны. Аўтазборкі сама ствараюць гісторыю версій (#95 AC4); runbook
фіксуе працэдуру выбару старой версіі і адкату.

Спека: `docs/superpowers/specs/2026-11-17-phone-builds-eas/spec.md`.

## Acceptance criteria

1. [ ] Мерж PR з кодам у main → з'явілася хмарная зборка sandbox-APK; у PR
   прыляцеў каментар: спасылка на старонку зборкі + QR + кароткі «як
   усталяваць»; спасылка таксама ў job summary.
2. [ ] Мерж docs-only PR → зборка не запускаецца; фільтр deny-by-default
   (невядомы новы шлях = збірае), агульны docs-only шоў пераўжываецца без
   другой копіі спіса шляхоў (гл. скіл-правіла «Search before adding
   helpers»).
3. [ ] Падзенне хмарнай зборкі → чырвоны статус на main і каментар у PR пра
   падзенне са спасылкай на лаг зборкі; «зялёная прыкмета» пры упадку не
   з'яўляецца (#95 AC5: не лічыць PASS пры няўдачы build/check/upload).
4. [ ] Ручны запуск workflow (workflow_dispatch) працуе без мержа.
5. [ ] Зборка ідзе ў хмары: CI-ранер не збірае gradle/node_modules native
   часткі — ён толькі адпраўляе зборку ў EAS і чакае спасылку.
6. [ ] Сакрэт-гігіена (#95 AC5): EXPO_TOKEN толькі ў GitHub secret, не ў
   гіце/лагах/каментарах; падзенне пры адсутным сакрэце дае чырвоны статус з
   агульным тлумачэннем без значэння сакрэту.
7. [ ] Трыгер не прымае код/сакрэты з недаверанага PR і не абыходзіць required
   checks; улічаны набор required checks branch protection (новы чэк не ламае
   guard-required-checks).
8. [ ] Гісторыя версій (#95 AC4): пасля ≥ 3 аўтазборак каталог білдаў у хмары
   паказвае versionName, versionCode, commit SHA, дату і статус; у runbook
   запісана працэдура выбару старой версіі і вяртання да яе (з улікам
   Android downgrade і магчымай страты лакальных тэставых даных — не абяцаць
   захавання, калі Android патрабуе выдалення апкі).
9. [ ] Негатыўны ахоўны тэст (#95 AC7): праверка падае, калі release
   пазначаны апублікаваным без APK, правільнага package ID, подпісу, SHA або
   працоўнай спасылкі.
10. [ ] Runbook дапоўнены (#95 AC7): трыгеры аўтазборкі, ручны запуск, што
   рабіць пры падзенні, гісторыя і адкат; па-беларуску.

## Out of scope

Аўтазборка на кожны PR; OTA/EAS Update (PHONE-03); production-профіль і
submit у сторы; змены required checks і branch protection; першая ўсталёўка
на фізічнай прыладзе (гэта PHONE-01, тут толькі працэдуры ў runbook).

`Blocked-by: #322`

## Proof

- Вынік workflow: журнал аўтазборкі пасля рэальнага мержа + каментар у PR са
  спасылкай зборкі (для змястоўнага і для docs-only PR — адваротны выпадак).
- Вынік негатыўнага ахоўнага тэста: падзенне пры штучна «апублікаваным»
  release без APK/правільнага package/подпісу/SHA/спасылкі.

## Notes for the dispatcher

Забарона issue-workflow §7: агент не рэдагуе `.github/` — стварэнне/змена
workflow патрабуе санкцыі ўласніка (прэцэдэнт #138). Без санкцыі — blocker
(agent:blocked) з канкрэтным запытам, не абыходзіць забарону. Сакрэты не ў
issue/PR. Ліміт хмарных зборак праверыць на expo.dev pricing і запісаць у
runbook.
