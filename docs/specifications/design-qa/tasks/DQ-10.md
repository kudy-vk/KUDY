# DQ-10 — Run visual:check in the Android CI workflow

## Epic

Epic: #908

## Goal

Every run of `android-e2e.yml` produces a visual report as an artifact, without blocking merge until stable (spec §8.1, §12). Since the owner decision of 2026-11-04 the workflow starts only by hand; on pull requests the same report comes from the local run in `docs/agent-rules/android-e2e-local.md`.

## Sources

Spec: `docs/specifications/design-qa/2026-10-30-design-qa-system.md` (sections cited per criterion). Canon: `docs/design/visual-language.md`; decision register: `docs/design/brand/decisions.md` (only rows marked accepted are rules). Record the git commit the sources were read at.

## Acceptance criteria

1. [ ] A step in `.github/workflows/android-e2e.yml` runs `visual:check` after the existing suites and always uploads the report and diffs as an artifact.
2. [ ] The step is not a required merge check; the result states this and the stability criterion (fewer than 1 false failure in 20 runs) for making it one.
3. [ ] A wiring test fails if the step or the artifact upload is removed (`docs/agent-rules/implementation-rules.md` rule 1).

## Out of scope

Running the design-QA agent in CI (owner decision: on request only).

Blocked-by: #910, #913

One manual run of `android-e2e.yml` with the artifact linked in `docs/agent-tasks/results/DQ-10.md`.
